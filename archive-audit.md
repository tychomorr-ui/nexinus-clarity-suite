# XinUS Clarity Suite Archive Audit

## Scope and Preservation Rule

The supplied `fullproject.tar.gz` archive is a TypeScript monorepo originating from Replit. Its browser-facing product scope consists of the principal XinUS web application, five companion applications, a shared Express API server, a shared Drizzle/PostgreSQL database package, and a shared stream-parsing protocol. The separate `crypto/` Solidity project is a retained source artifact and is not part of the managed web runtime. The modernization preserves the verified terminology, routes, feature boundaries, data concepts, and workflow contracts listed below while replacing the delivery stack with React, tRPC, Drizzle/MySQL, and protected Manus authentication.

## Service Contract and Business-Rule Inventory

| Original API route | Request contract | Verified original behavior to preserve |
|---|---|---|
| `POST /api/xinus/clarity` | `problem`, mode, optional attachments | Sanitizes input, drives adaptive DXNS state, preserves bounded per-user history, emits streaming state/content events, supports `core`, `expand`, `ascend`, `transcend`, `light_warrior`, and owner-only `omni` modes. `transcend` is deterministic and classifies avoidance, fear, indecision, overthinking, misframing, affirmation, or unclear input. |
| `POST /api/ged/tutor` | `subject`, up to 20 tutor/student turns, `studentTurn` | Requires one of Math, RLA, Science, or Social Studies; streams a short reflective tutoring response; provides reset, stop, offline, and error behavior in the client. |
| `POST /api/xinus-gems/appraise` | Image data URL and optional 500-character hint | Validates photo MIME and 8 MB cap, emits a structured appraisal, supports coin detail, exposes unusable-photo results, gives a first-appraisal XC bonus, and refunds XC when the service fails before delivery. |
| `POST /api/xinus-office/assist` | Message and up to 16 chat turns | Streams executive-assistant work, including document, table, slide-outline, budget, calculation, and plan formats. |
| `POST /api/sitrep/assess` | `situation`, optional context, `general`/`travel`/`immigration` mode | Streams a structured Risk Level, Best Choice, Avoid, SitRep Summary, and Suggested Actions report. The immigration mode includes a legal-information disclaimer. |
| `POST /api/wraith/converse` | Message, up to 12 turns, persona name/tone/intensity/omni flag | Streams concise voice-first assistant output. Persona changes name and tone only; its base safety contract remains fixed. Omni awareness can guide the user to other XinUS modules. |
| Authentication routes | Provision, login, logout, current user, password rotation | The original system used issued sessions plus auth auditing; the modernization maps protected access to Manus auth while retaining access-control and audit concepts. |
| Billing and credit routes | Billing state, checkout, credits | The original app models core versus Plus access, weekly quotas, and XC ledger balances. Actual payments require a configured payment provider before activation. |
| Owner routes | Owner key and terminal command | The original app gates audit statistics and command history behind owner verification and records terminal actions. |

## Verified Forms and State-Specific Views

The core Clarity form is a text composer with attachment intake, mode controls, retry, reset, Light Warrior follow-up, and owner-only Omni unlocking. The core owner screens include an owner-key password control, command search, outcome filter, and command composer. The account screen includes current, new, and confirmation password fields. The Hologram surface includes a file input and a Clarity prompt.

The GED Tutor page includes Math, RLA, Science, and Social Studies tabs; a subject-specific conversation; a multiline learner composer; reset; stop while streaming; explicit offline handling; and streamed partial-answer handling. The Hidden Gems page includes camera or file selection, an optional context hint capped at 500 characters, cancellation, quota and XC indicators, an upgrade surface, unusable-photo recovery, a structured appraisal display, coin-detail display, sale-channel links, cautionary information, and an appraise-another action.

PD Pro includes case-name and optional-client forms, a voice or note input containing task/deadline extraction, and an Office composer for memo, table, budget, presentation outline, calculation, or related work. The Recidivism workspace includes subject creation; trigger situation, place, person, and observation inputs; obligation title, date/time, and type; geofence name, numeric radius, and address; contact name, role, and telephone; role selection; subject/anchor dashboards; a printable report; panic/SOS controls; and a voice-capable command console.

## Naming and Design Conventions

The original source uses `XinUS`/`XINUS` for the suite identity, `NEXINUS` for the historical public product label, `Wraith` for the voice-first assistant family, `XC` for the credit or coin concept, and explicit domain names for companion modules. The modernization will use **XinUS Clarity Suite** in new product-facing metadata and navigation while retaining original module labels in every feature area found above. Original PWA and offline affordances are preserved as modern responsive loading, empty, error, cancellation, and connectivity states. The original visual language is dark, typographic, atmospheric, and state-driven; the new design system will retain this depth while supplying clearer hierarchy, calmer spacing, accessible contrast, and a consistent responsive dashboard shell.

## Verified Owner-Terminal Correction

The original `GET /api/owner/terminal-history` route accepts only `ok`, `error`, and `pending_confirmation` as an `outcome` query filter. The original `POST /api/owner/terminal` route persists `ok`, `err`, or `pending_confirmation` to the database. This is a verified legacy inconsistency: a query for `error` does not match the persisted `err` value. The modernization will preserve the terminal workflow while resolving the representation at the typed server boundary so filtering reflects persisted command outcomes consistently.
